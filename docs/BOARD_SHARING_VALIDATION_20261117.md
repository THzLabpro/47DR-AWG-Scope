服务现使用 `G:\pkg\02_project\host\shared_service_20261117_v07\lab_config_v5.json`，仍由 SYSTEM 计划任务 `FPGA_BoardShare_v2` 开机启动，TCP 4749。旧任务 `47DR V2.1 Remote Service` 已禁用并停止，原 4748 监听已撤下；旧任务定义保留，可恢复。UDP 9001 防火墙规则只将程序路径更新为 v07，板卡来源与目标地址限制不变。

本版修正两处交接检查：47DR 清理须同时确认 `running=0`、`busy=0`、`cap_busy=0`、`ps_ready=1`、`fault=0`；运行任务因结束使用或断线而抛出取消异常时，只有停止与连接清理通过才取消旧任务并继续队列。真实错误或清理失败仍进入待恢复。RF-UDP 即使串口退出失败也会继续尝试关闭 UDP 和停止板卡输出，任何失败都阻止交接。

验收采用同一客户端电脑上的两个原生窗口及独立身份“交接验证甲／乙”，Qt 使用 offscreen 后台运行，服务和板卡均为实物。只跳过了姓名与提交确认对话框，实际使用原窗口的提交、轮询及 `closeEvent`。这不等于两台客户端电脑分别操作的人工验收。

- 47DR 下载 4096 点零波形并启动播放，确认 `running=1`；结束使用后重新打开数据连接，读回五项停止／就绪检查全部通过。
- 47DR 播放期间，RF-UDP 原生窗口提交串口采集并排队；关闭 47DR 窗口后，RF-UDP 自动完成加载并取得使用权，无需二次开始。
- RF-UDP 流量测试运行期间，47DR 窗口提交状态查询并排队；关闭 RF-UDP 窗口后，旧测试退出，47DR 自动加载，随后 ADC0 回采 4080 点成功。
- 模拟甲客户端失联但不发送结束请求：20 秒时仍归甲；30 秒宽限超时后服务自动停止、释放并加载乙的 RF-UDP 工程。从断线到乙串口任务完成约 101.8 秒，包含宽限和固件初始化时间。
- 乙最后关闭窗口后，状态为 `ready`、使用人为空、队列为空。独立进程可重新打开 COM6、重新绑定 UDP 9001，确认服务已经释放这两项资源。结果保存在 `host/app_data/board_share_validation_20261117/native_handoff_v07.json`。

`cleanup_validated=true` 的验收含义为任务停止、控制状态读回和软件连接释放；这是自动交接的数字控制条件，不是仪器测得的 RF 端口零功率。后者、长时间稳定性及物理层 BER 不在本次交接通过范围。软件回归 29 项通过，原生窗口离线检查 2 项通过。

两套客户端重新打包至 `host/dist/shared_clients_20261117_v07/`，均通过独立 exe 创建原生窗口并关闭的检查。日常无参数启动脚本默认进入共享模式；需要显式模拟器等参数时仍保留原入口。实验室使用 v07 服务，旧 v04 包内服务已过时，不要启动。

新服务已安装为 SYSTEM 计划任务 `FPGA_BoardShare_v2`，设为开机启动，使用 v4 配置；安装前检查固件哈希通过，任务返回 Running。此项不是整机重启验收。启动脚本及安装脚本已同步使用 v4 配置。原 4748 入口仍存在，尚未完成全局入口收口。

计划任务启动的新服务随后完成 RF-UDP 初始化及预热后的复测：166 包发送、166 包正确接收，丢包、重复、CRC、载荷错误均为 0；测试判定 PASS，遥测增量 `udp_9000_rx=166`、`reasm_ok=166`，丢弃及在途均为 0，业务包计数一致性检查通过。本轮事件包含 48 个 UDP 事件与 281 个串口事件。测试结束后已请求停止测试、关闭 UDP/串口并结束使用；服务按未启用自动交接的配置进入待恢复，队列为空。

RF-UDP 初始化、另一身份查看使用人、47DR 排队和取消已实测；此前显式 RF-UDP → 47DR 恢复后，47DR 零波形下载、CRC 及回采复验通过。这些结果不代表跨工程自动交接通过。两套配置仍保留 `cleanup_validated=false`；结束测试后进入待恢复，非零 RF 输出停止仍需现场测量。

## 已实现

47DR 与 RF-UDP 保持各自原有界面，增加同一套原生共享状态条：使用人、工程、队列、已登记固件版本、结束使用和恢复。首次登记姓名后，身份保存在当前 Windows 用户的本地应用数据目录；姓名可以修改，不用导入领用文件，不填写预计时间。

实验室调度器串行执行冻结后的任务；只有当前实验持有人可以继续操作。关闭或结束使用触发服务端清理，清理确认后自动运行下一位已经提交的动作。心跳宽限为 30 秒；失联等待者取消排队，失联持有人触发清理。服务重启进入待恢复状态，排队和运行任务不重放。更换固件包文件后，原任务被拒绝。

47DR 数据路径由真实 Python 驱动接入调度器，波形打包和回采分析留在本机。RF-UDP 使用现有 MixedParser、遥测解码和流量测试模块，实验室适配器承担初始化、串口、UDP 测试、换挡、LMS 和 DAC 电流操作；客户端不运行硬件命令。

## 复现

在 47DR 工程根目录运行，RF-UDP 源码目录需另加入 `PYTHONPATH` 才能执行 RF-UDP 窗口检查：

```powershell
$env:PYTHONPATH=(Resolve-Path 'host/tools').Path + ';' + 'RF-UDP源码根目录'
$env:QT_QPA_PLATFORM='offscreen'
$env:PYTHONUTF8='1'
$env:AWG_APP_DATA=Join-Path (Get-Location) '过程文件/板卡共用/test_app'
py -3 -m pytest host/tools/board_share host/tools/awg_eth/tests/test_remote.py host/tools/awg_gui/tests/test_program_menu.py host/tools/awg_gui/tests/test_remote_gui.py host/tools/awg_gui/tests/test_gui_emulator.py -q --basetemp '过程文件/板卡共用/pytest_final'
```

新客户端候选通过构建脚本生成；打包后的窗口检查使用 `--shared-smoke 输出JSON路径`，并设置 `QT_QPA_PLATFORM=offscreen` 和 `QT_QPA_FONTDIR=C:\Windows\Fonts`。该入口禁止自动连接服务，只检查窗口创建、截图与正常退出。
